## Что делегировал

Каркас решения и docker-обвязку, генератор seed-данных, вёрстку компонентов, черновики тестов,
разбор моих прошлых проектов для выбора раскладки слоёв.

## Что проектировал сам

Границы слоёв и состав проектов, набор эндпоинтов и контракты, бизнес-правила: трактовку
Refunded и Cancelled, формулы KPI, правило предыдущего периода. Требование обойтись без Dapper,
без MediatR и без лишних слоёв — тоже моё.

## Где агент ускорил

Шесть проектов со связями, пакетами и Dockerfile — минуты вместо часа. Seed на 3500 продаж
с сезонностью, отпусками и разной маржинальностью — самая долгая часть, если писать руками.
Перевод всего слоя стилей на CSS-модули за один заход.

## Где ошибся и что я исправил

- **Экономика в seed.** Скидка накладывалась на наценку без потолка: 5 % позиций уходили ниже
  себестоимости, маржа по дронам падала до 3,5 %. Нашли не глазами по коду, а SQL-разрезом
  по категориям сразу после первого сида.
- **Комментарии.** Наплодил пояснений в каждом файле, включая Dockerfile и compose. Убрали все.
- **Магические строки и числа** по всему коду — вынесли в константы и в `locales/ru.ts`.
- **Пиксели вместо относительных единиц**, и в первой попытке правки — только частично.
- **Таблица не влезала в карточку** и ломала контейнер: 904 px внутри 885 px. Заметил
  на скриншоте, починили `overflow-x` и сокращением отступов.
- **`docker image prune -a`** заодно снёс уже скачанные базовые образы — час ушёл на перекачку.
- **Vite 8 из шаблона** не запускался локально: npm не ставил нативный биндинг rolldown.
  Откатились на Vite 7.
- **Базовая сущность.** Агент задал вопрос один раз, не получил ответа и молча решил обойтись
  без неё, вместо того чтобы переспросить.
- **Проверка юзингов на инкрементальной сборке.** Отчитался, что лишних нет, хотя анализатор
  по неизменённым проектам просто молчит: на полной пересборке их оказалось 18.
  Отсюда правило в проекте — чистить юзинги только на зелёной сборке и проверять
  через `--no-incremental`.

## Что отклонил

Dapper для рейтинга, MediatR и CQRS на восьми read-only эндпоинтах, submodule ради двух
репозиториев, generic-репозиторий, отдающий сущности целиком.

## Как проверял

Сборка и тесты после каждого этапа. Seed — запросами к живой базе: объёмы, период, распределение
статусов, сезонность, разброс менеджеров, маржа по категориям. Ответы API сверил с прямыми SQL —
выручка, прибыль и количество совпали до копейки. Границы периода проверил арифметикой:
`[08-25..09-01]` = `[08-25..08-31]` + `[09-01]`. Сгенерированный EF SQL смотрел в логах.
Состояния UI гонял в браузере: пустой период, погашенный бэкенд, смена периода без скелетонов,
поведение при зуме 125–200 %. Полный прогон `docker compose down -v && up --build` с нуля.
